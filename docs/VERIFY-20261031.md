## 4. 迁移过程中发现并修正的 4 个问题

| # | 问题 | 影响 | 处置 |
|---|---|---|---|
| 1 | workflow 级 `env` 使用了 `runner.temp` 上下文 | GitHub 判定整个工作流无效，push 触发的 run **没有任何 job** | 改用 step 内 `$RUNNER_TEMP` + `--session` 显式传参 |
| 2 | runner 默认 UTC | `data.js` 的 `generatedAt`、台账时间戳、导出文件名比旧通道差 8 小时，P5-5 会被误判为过期 | 工作流锁定 `TZ: Asia/Shanghai` |
| 3 | 部署期把 6 位口令注入 `autotc.user.js` | 口令重新出现在公网产物，直接违反 P5-9 与 §P3 的设计意图 | 取消注入，改为手机首次上报时弹框输入并存本机 localStorage；产物零凭据 |
| 4 | `aininja365.xyz` zone 的 Browser Cache TTL 把静态资源压到 4 小时（覆盖 Pages `_headers`；旧通道同样如此，属既有配置） | 发布后最长 4 小时仍可能取到旧 `data.js` | 不动 zone 设置（护栏 6），发布前用 `stamp_assets.py` 刷新 `?v=`；HTML 本身 `no-store`，换 query 即刻生效 |
